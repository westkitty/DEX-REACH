This is source preparation, not installed or general production acceptance. C13 remains NOT PASS; E7 HOST CAPABILITY BLOCKED; C14 PROGRAM PARTIAL; C15 BLOCKED. A local-runtime-only exception requires explicit owner approval for the eventual window. No production tag is authorized.

## Changes from 0.3.2

The C14 preflight now binds a versioned candidate to the dedicated `/Users/andrew/dex-reach-release` checkout, canonical `westkitty/DEX-REACH`, the full approved SHA, actual package version and the exact current remote main tip. Resolved SSH/HTTPS GitHub transport spellings are accepted; lookalike repositories refuse. All 30 prerequisite gates remain. Source drift during evidence collection refuses. Missing GitHub credentials, malformed/truncated data, duplicate required runs, failed/skipped/cancelled/incomplete checks and historical PR evidence cannot establish mainline readiness. Required jobs belong to the exact main push workflow suite; CodeQL additionally requires the exact successful CodeQL push workflow.

Native processes now wait behind a fixed POSIX stdin barrier. Before spawn, the activity writer fsyncs an attempt-bound intent. The waiting process's PID and platform start identity are committed before releasing the barrier to `exec` the previously authorized program. The original command guard, execution profiles, allowed roots, secret sanitization, task identity and time ceilings remain. Launch-evidence or result-evidence failures never resolve as normal success. The execution time budget starts after binding; the launch stage has a separate bounded deadline. Signal and timeout outcomes remain uncertain, without an invented numeric status. Fast exits preserve their actual status and output evidence.

Intent is stored in version 1 `activity/launch-intents.json`. The original `activity/processes.json` retains its positive-PID C13 schema. A crash between committing a bound row and removing the corresponding intent is read as one bound activity; a contradictory binding refuses. Unbound intents stay uncertain at boot and are never treated as a dead PID or replay authorization. Active intents and processes cannot be silently evicted to make room in the bounded ledger. C13 ignores the additive sidecar and retains its existing conservative missing-activity recovery. This is source compatibility; physical rollback remains unverified.

Process deadlines accept finite numbers only. Omitted `timeoutMs` retains the 15-second default; finite values retain the existing 100–60,000 ms clamping. Strings, booleans, null, objects, NaN and infinities refuse before launch. The execution closure checks the normalized bound before intent creation; the separate launch deadline remains 35 seconds and the execution deadline starts after durable binding. Both timers are cancelled when the child settles, including failed binding and uncertain termination. No security finding is suppressed or waived.

## Versions and limitations

- Package, lockfile root and runtime version: 0.4.0.
- Transport integer protocol: 1; negotiated semantic protocol versions remain 1.0 and 2.0.
- Durable task-store schema: 1. Launch-intent sidecar schema: 1. Release-candidate identity contract: 1.
- Backup, authorization, receipts and manifests retain their existing contracts. No owner-state migration or credential change is performed by source preparation.
- Six moderate transitive production advisories remain; the high/critical audit gate is unchanged.
- PID start identity uses the existing platform facility. Missing identity refuses launch; older records remain unverifiable. Identity does not prove an arbitrary command's external effect or the fate of detached descendants.
- Unbound intents need owner reconciliation and can exhaust the bounded activity capacity; they are deliberately not auto-deleted or replayed.
- The separate DEX command mappings remain absent. No DEX repository changes or product conformance claims are made.

Installation requires the separate [maintenance packet](0.4.0-maintenance-window.md), exact post-merge CI, a fresh approved identity, verified complete backup/restore and all live gates. A changed candidate or invalidated capture can require a new backup and owner decision. Retain C13 Last Known Good; never blind-retry an uncertain transaction.
