## 12. Current Change Scope and Impact Radius

The branch migrates the MCP dependency from the monolithic `@modelcontextprotocol/sdk` 1.30 to the v2 package split (`server`, `client`, `node`, `express`, `server-legacy`) at 2.0.0, and zod from 3 to 4. The sessionful `/mcp` route is preserved by `NodeStreamableHTTPServerTransport` from `@modelcontextprotocol/node`, whose `handleRequest(req, res, body)` shape matches the v1 transport it replaces, and the gateway's own OAuth authorization server is preserved by the official `server-legacy/auth` migration bridge. No tool name, description, annotation, schema or ordering changed, and no DEX authority path was touched. Served protocol semantics are deliberately unchanged in this phase; dual-era serving is separate work.

The branch also adds `src/shared/profiles.ts` and the `workspace-safe` execution profile. Owner modes are unchanged at OFF/READ-ONLY/ON; this is a node-side execution profile, configured locally through `DEX_REACH_PROFILE`, that narrows what ON can reach on that node. It admits inspection, file reads, typed writes, checkpoints, planning and the declared-safe compatibility tools, and refuses arbitrary `dex.process.run`, the process and session compatibility tools, privileged and destructive surfaces, safety configuration mutation, and any adapter tool or operation the catalog does not classify. The refusal is evaluated against the node's own configured profile rather than the effective profile an authorization decision produced, because READ-ONLY replaces that effective profile and reading the constraint from it would let READ-ONLY re-admit exactly what the profile refuses; both narrowings apply and neither may widen the other. A planned commit inherits its target's admission, and a compatibility target defers to the exact tool. `dex explain` now reports the policy decision and the profile constraint separately along with whether the operation would actually run. No installed node's profile changed and the default remains `development`.

The branch also adds `src/shared/trace.ts` and end-to-end causal tracing. A request carries a W3C Trace Context from the MCP edge through the gateway and node into authorization, planning, commit and execution, and the node returns the `traceId` to the caller so a completed action can be reconstructed afterwards. Spans are an allowlist of identifiers, stage, outcome and hashes: arguments, file content, process output, raw plan arguments and credentials are structurally refused, a refusal is traced as an outcome class with its message deliberately omitted, and `baggage` is never accepted at all. Inbound `traceparent` is continued only when well formed and `tracestate` only when it validates within W3C bounds; malformed context starts a fresh trace rather than being repaired. Trace storage is local, bounded and outside Git, and OpenTelemetry export is off unless the owner sets `DEX_REACH_OTEL_EXPORT=1`. Two owner CLI commands, `trace` and `traces`, read it back. This phase adds no MCP action, no capability, no dependency and no authorization path; tracing observes decisions and never makes one.

The branch also adds `src/shared/operations.ts`, one catalog holding DEX operation authority metadata: capability, risk class, mutation, plan eligibility, READ-ONLY admission, workspace-safe eligibility and checkpoint strategy for every routed operation, plus a risk classification for all 26 compatibility adapter tools. Capability mapping, READ-ONLY admission, plan targets, checkpoint strategy and the remote compatibility block list now derive from it instead of being restated in `capabilities.ts`, `access.ts`, `node/main.ts`, `gateway/mcp.ts` and `compatibility.ts`. This phase intentionally changes no authorization outcome; parity with the pre-catalog implementation is asserted by test across every operation including unknown ones. `dex.commitPlan` declares that its risk inherits from its planned target rather than carrying a fixed class, and `node/native.ts` gained a second catalog-driven READ-ONLY refusal behind the existing one.

The branch also adds a local capability-request lifecycle in `src/shared/capability-requests.ts`. AI may request a capability, roots, duration and optional use cap; that record is not authority. Only local owner approval creates an ordinary `CapabilityGrant` (the request id is reused as the grant id so retries cannot mint a second grant). Owner approval may narrow and cannot widen. Deny and expiry create no grant. Raw target arguments are not stored. `dex.capability.request` is a classified node operation but is not a public MCP action, so the 16-action contract is unchanged. Added DEX-INV-030.

The branch also adds rolling execution budgets in `src/shared/budget-policy.ts` and `src/shared/budget-usage.ts`. Runtime usage counters are stored separately from AccessState so they cannot change the owner policy hash or invalidate unrelated plans. Budgets only narrow: OFF, READ-ONLY, workspace-safe, client ceilings and grants still win, shared and per-client ceilings intersect by minimum, a preauthorization denial consumes nothing, and a successful reservation keeps its rolling cost after later execution failure while releasing only the inflight concurrency slot. Missing or corrupt budget policy is unrestricted because owner policy remains the authority source; corrupt usage with a real policy fails closed. Canonical lock order is access lock then budget lock; the budget modules never acquire the access lock. Owner CLI: `budgets`, `budget set`, `budget clear`. Added DEX-INV-029. No MCP action and no dependency change.

The `claude/work-coordinator-cpcug3` branch adds a local shared-machine work coordinator: `src/shared/machine-capacity.ts` (host measurement and deterministic slot/pressure policy), `src/shared/work-coordinator.ts` (leases, FIFO queue, bounded history), seven `work-*` owner CLI commands, and invariants DEX-INV-022 through 026. Coordination state lives under `~/.dex-reach/coordinator/` at mode 0700/0600 and is excluded from Git by the existing `.dex-reach/` ignore rule. The change adds no MCP action, no capability, no dependency, and no authorization path: `authorizeOperation` is untouched and a regression test asserts that holding a lease leaves its outcome identical. Machine admission and execution authorization stay separate decisions that must both pass.


The branch now also adds an owner-visible process activity ledger in `src/shared/activity.ts`. Native `dex.process.run` records the actual child PID at spawn, and compatibility `start_process` records the adapter-reported PID; finished, failed, timed-out, terminated and externally exited states remain bounded as owner evidence. The persistent record stores only activity id, kind, state, PID, operation, a bounded executable label, timestamps and local cwd metadata — never raw command arguments, prompts, transcripts, stdout/stderr or credentials — and corrupt activity evidence fails visibly instead of silently disappearing. `dex activity` merges those process records with coordinator leases/tickets, live gateway/node service identities and anonymous heavy blockers; `--share` removes local PIDs and paths.
